# 测试计划

## 1. 测试目标
- 对 `testing/sut/app.py` 暴露的 16 个接口做 L0 手工接口测试。
- 覆盖正常、异常、边界、权限、金额与状态流转。
- 对疑似缺陷用独立请求复现，只记录有真实响应证据的问题。

## 2. 测试范围
- 认证：登录、登出、token 有效性。
- 用户与权限：用户详情、管理端订单。
- 商品：列表、详情、创建、上下架。
- 订单：创建、详情、我的订单。
- 支付：发起支付、支付回调。
- 评价：创建评价、评价页 HTML 输出。
- 系统：健康检查。

## 3. 暂不测试
- 前端页面与后端实现。
- 性能、并发、CI、UI 自动化和 pytest 自动化。
- `testing/legacy/` 代码审查。
- 支付回调的有效签名场景；当前文档未给出签名算法，只做伪造回调与异常回调检查。

## 4. 方法与工具
- 使用 Apifox 批量执行 56 个请求作为初筛。
- 对失败项和重点风险用 `curl` 在独立端口 `18081` 上复现。
- 对需要干净数据的用例，使用临时目录中的 SUT 副本，避免污染仓库内 `sut.db`。
- 每个缺陷保留可直接执行的 curl 命令、实际状态码和响应片段。

## 5. 结束条件
- 16 个接口至少各执行 1 条用例。
- 正常、异常、边界用例均有记录。
- 至少 4 条缺陷有真实请求证据。
- Apifox 中因工具或导入导致的结果不再作为缺陷结论。
- 未覆盖内容在测试报告中如实说明。
